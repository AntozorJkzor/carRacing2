# Деформация шин и доработка их физики

## Зачем

Шины сейчас — **точка контакта**. Raycast даёт одну `hit_point`, Pacejka считает Fx/Fy от κ/α и Fz, визуал — жёсткий цилиндр/GLB колеса, центр = `hit_point + up * radius`.

Нет: пятна контакта, сплющивания, боковины, давления, температуры, износа, разных покрытий. На горной дороге это читается как «едет на катке».

Цель — **деформация как часть модели силы**, а не только скин. Визуал следует за тем же сжатием, что и физика.

## Что есть сейчас

Описано в `phisyx.md`. Кратко:

| Кусок | Файл | Поведение |
|-------|------|-----------|
| Контакт | `car_controller.gd` `_update_suspension` | Один луч вниз, spring+damper |
| Силы | `tire_model.gd` | Pacejka B/C/D/E, эллипс, лёгкий load sensitivity |
| Состояние | `wheel.gd` | ω, κ, α, Fz, Fx, Fy, нет radius_effective |
| Визуал | `visual_wheels.gd` | жёсткий радиус из `CarSetup` |
| Размер | `wheel_layout_editor.gd` | ISO: rim / width / aspect → radius |
| µ | `tire_mu_front/rear` | Константа, нет surface |

Подвеска уже сжимается; шина — нет. Fz = сила пружины, не «объём резины».

## Целевая модель (практичная)

Не полный FEM покрышки. Два слоя:

1. **Вертикальная деформация (contact patch)**  
   Шина — пружина между диском и землёй, жёстче подвески.  
   `radius_eff = radius_unload - tire_deflection`  
   Fz_tire = f(deflection, pressure, speed)  
   Подвеска считает длину до **центра диска**, шина — остаток до земли.

2. **Горизонтальная деформация (lag / carcass)**  
   Боковина как мягкий лаг α и κ (first-order filter): сила не прыгает за один substep. Это сильно меняет feel на неровностях.

Визуал: сплющить меш по оси `up` на `deflection`, опционально растянуть пятно по `forward/right` пропорционально Fx/Fy.

## Этапы

### 1. Разделить подвеску и шину

Сейчас луч часто бьёт в землю на длине rest+travel, а радиус только для визуала.

Нужно явно:

- луч / капсула до земли
- `disc_height` от кузова (пружина подвески)
- `tire_deflection = radius_unload - (disc_to_ground)` clamped 0..max_deflect
- если диск слишком высоко — отрыв (`on_ground = false`), deflection = 0

Поля в `CarSetup` / колесо:

- `tire_pressure_bar` (например 1.8–2.5)
- `tire_vertical_stiffness` или вывод из давления и ширины ISO
- `tire_max_deflection` (доля радиуса, ~12–20%)
- `tire_carcass_relax` (1/s) для лага α/κ

`wheel.gd`: `deflection`, `radius_eff`, `patch_length`, `pressure`.

### 2. Сила Fz от шины, не только от пружины

Вариант A (проще): оставить spring подвески как есть, **добавить** параллельную шинную пружину только в визуал+малый Fz. Слабый эффект.

Вариант B (правильный): Fz контакта = шинная пружина(+лёгкий damper резины); подвеска работает между кузовом и диском. Это меняет питч/крен — тестировать Golf/Volga отдельно.

Начать с B на одном авто, сравнить телеметрию F4 (`car_telemetry.gd`).

Load sensitivity в `tire_model.gd` уже есть — связать D с `radius_eff` (сжатая шина чуть другая µ-кривая).

### 3. Пятно контакта и combined slip

Сейчас одна точка → один κ/α.

Минимум:

- эффективная скорость точки с `radius_eff` (уже влияет на κ)
- сдвиг hit_point назад/вбок на малую долю patch при больших Fx/Fy (trail) — стабилизирует прямую

Позже (не блокер): 2–3 луча по ширине шины (`front_tire_width_mm`) для камбера и ребра на колее.

### 4. Покрытия

Горная дорога: асфальт / грунт / трава / мокрое.

- physics layers или `surface` с луча (`collider.get_meta("surface")` / материал)
- таблица µ_scale, rolling_resistance, шум
- не путать с `tire_mu_*` машины: `mu_eff = tire_mu * surface_scale * temp_scale`

### 5. Температура и износ (после деформации)

- нагрев от |κ|·Fx + |α|·Fy
- остывание на воздухе
- µ peak чуть растёт в рабочем окне, падает при перегреве
- износ медленный, влияет на D; сброс в гараже

Не делать в том же PR, что вертикальная деформация.

### 6. Визуал деформации

В `visual_wheels.gd`:

- scale по `up`: `(radius - deflection) / radius`
- центр ближе к земле на `deflection` (уже частично: `hit_point + up * radius` → `hit_point + up * radius_eff`)
- лёгкий squash по ширине, если aspect высокий (боковина)

Шейдер покрышки (нормали «подушки») — опционально, когда CPU-scale выглядит плоско.

Дым (`wheel_smoke.gd`) уже от slip — порог по deflection+κ.

## Порядок внедрения

1. `radius_eff` в физике κ + визуал центра (уже заметно)
2. Вертикальная пружина шины + clamp deflection
3. Лаг carcass для α/κ
4. Surface µ
5. Давление в UI
6. Температура / износ
7. Несколько лучей по ширине

## Риски

- Две пружины (подвеска + шина) без демпфера резины → высокочастотный jitter. Нужен rubber damper и substeps (уже 4).
- Слишком мягкая шина съест travel подвески — машина «сидит на резине»
- Слишком жёсткая — снова каток
- Golf FWD: изменение Fz спереди под газом снова ударит по lat-priority — проверять маятник
- ISO radius из layout должен совпадать с unload radius деформации
